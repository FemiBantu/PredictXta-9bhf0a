## 6. AI Providers

| Provider | Role |
|----------|------|
| **OpenAI** (GPT-4o / GPT-4 Turbo) | Primary LLM for AI reports and reasoning |
| **Google Gemini** (1.5 Pro / Flash) | Secondary LLM; cost-optimised fallback |
| **Anthropic Claude** (3.5 Sonnet) | Tertiary; used for structured data extraction |
| **Llama via Groq** (llama-3.1-70b) | Low-latency fallback; configured where available |

> **Non-negotiable rule:** LLMs are **never** the sole numerical probability engine. All win/draw/loss probabilities are generated by deterministic quantitative models (Elo, Poisson, Dixon-Coles, Bradley-Terry). LLMs receive the model output and generate reasoning, explanations, and risk summaries anchored to ±8% of the quantitative anchor.

## 12. Feature Flags (Kill Switches)

Feature flags live in the `feature_flags` database table. All 30+ flags follow the naming convention `{category}_{feature}`. Flags can be toggled in the OnSpace Cloud Dashboard → Data → `feature_flags` table without a deployment.

Key flags:
- `sport_{name}` — enable/disable each of the 13 sports
- `data_removed_sports_guard` — blocks rejected sports at ingestion
- `prediction_quality_gate_v3` — enforces 7-stage prediction quality gate
- `quant_model_anchor` — clamps LLM probabilities to ±8% of quant model
- `provider_failover_circuit` — enables circuit-breaker auto-failover

## 13. Security Rules

1. **No credentials in source code.** All secrets use `Deno.env.get()` (Edge Functions) or `${{ secrets.* }}` (GitHub Actions) or `EXPO_PUBLIC_*` env vars (client — anon key only).
2. **JWT subject is authoritative.** User identity is always derived server-side from the JWT `sub` claim. Clients cannot supply or forge `user_id`.
3. **All entitlement decisions are server-side.** VIP status, admin roles, and coin balance are computed server-side at request time using the service role key.
4. **RLS on every table.** No table may exist without Row Level Security enabled and at least one policy.
5. **SECURITY DEFINER functions must set `search_path = public, pg_temp`.**
6. **Secret Scanning** is enforced in CI via `gitleaks/gitleaks-action@v2` — any commit containing a credential pattern blocks the build.

## 15. Date / Time Rules

- All timestamps stored in PostgreSQL as `timestamp with time zone` (UTC-normalised).
- Frontend converts UTC → user's local timezone for display only.
- Date navigation (`yesterday` / `today` / `tomorrow`) uses `services/dateUtils.ts` `buildDateRange()` which computes correct UTC window boundaries for any timezone (verified: WAT, UTC, EST, PST).
